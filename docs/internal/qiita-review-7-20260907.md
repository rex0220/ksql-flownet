# 【kSQL-FlowNet #7】CSV 入出力編 下書きの外部レビュー裁定(2026-09-07)

対象: docs/internal/qiita-draft-7.md(commit 803c969)。正本 docs/csv-io-operations.md にも同じ記述があったため、記事と正本の両方へ反映した。

| # | 指摘 | 裁定 | 反映・根拠 |
| --- | --- | --- | --- |
| 必須 1 | 完成パスへ直接 scp すると転送途中のファイルを cron が読み、その sha256 が baseline になる | 採用 | `.part` で転送 → 同一ディレクトリ内で `mv`(原子的 rename)して公開、の手順へ。SFTP なら put → rename。記事・正本の転送例と原則を修正 |
| 必須 2 | `csvxfer` は IO ルートに閉じ込められていない(通常シェル可)。root 以外の実行ユーザーでは 750/csvxfer 所有だと読めない。出力の可読性も要確認 | 採用 | 「IO ルート外へ書き込ませないための設定で閉じ込めではない。本番は `ForceCommand internal-sftp` + `ChrootDirectory` で SFTP 専用に」、「root 実行の例。実行ユーザー分離ではグループ/ACL で許可し、出力を csvxfer が読めるモード・グループを確認」を記事・正本に |
| 必須 3 | sha256 は差し替えの検出であって OS ロックではない。「途中で差し替えられない」は言い過ぎ | 採用 | 見出しを「差し替えは sha256 で検出され、同じ Run では再開できない」に、冒頭も「差し替えられた入力では同じ Run を再開できない」に。「実行中のファイルを OS レベルでロックしない。初回読取中の上書きまでは防げないため Run 開始後は触らない運用が前提」を記事・正本に |
| 必須 4 | 同じ Run の rerun-from で出力 sha256 が同じとは限らない(as_of は時刻関数の固定であってレコードのスナップショットではない) | 採用 | 「検証データを変更しない実機試験では同一。参照データが変われば同一 Run でも変わる」へ(記事・正本) |
| 補足 | `KSQL_FLOWNET_IO_RETENTION_DAYS` は自動削除ではなく再開拒否の判定値 | 採用 | 実装(`src/io/io-config.ts` は保持日数を INPUT_RETENTION_EXPIRED の判定にだけ使い、削除しない)と一致。記事・正本に明記 |
