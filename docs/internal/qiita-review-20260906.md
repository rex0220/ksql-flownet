## ChatGPT

| # | 指摘 | 裁定 | 反映・根拠 |
| --- | --- | --- | --- |
| 1 | Markdown のエスケープ崩れ(`\(`・`\|`・`\-` など) | 不採用(原稿の問題ではない) | リポジトリの原稿にはエスケープ文字は存在しない。レビューへ貼り付けた際の変換と判断。Qiita 投入時のプレビュー確認は投稿手順に含める |
| 2 | 「人が触るのは操作要求アプリだけ」はボード閲覧と矛盾 | 採用 | 「人が更新するのは原則として操作要求アプリだけ。実行管理・監査履歴は CLI だけが書き、人は参照」へ |
| 3 | 「新規レコード追加でしか受け付けない」は claim 前取消(既存レコードの `cancel_requested` 更新)と矛盾 | 採用 | 設計判断の「機械専用アプリ」を、要求レコード追加+取消フラグの例外を明示した文へ(仕様書 §8.1 と同じ整理) |
| 4 | 「受信ポート不要・固定 IP 不要」は条件付き(SSH 経路、kintone の IP 制限、npm/GitHub アクセス) | 採用 | 「通常実行時は HTTPS 発信だけ。kSQL-FlowNet のための受信ポート・公開ドメインは不要。SSH 経路と、IP 制限を使う場合の固定送信元 IP は別途」へ(導入手順書 §1 と同じ扱い) |
| 5 | 「失敗ノードから再開」を「成功済みは再実行せず、FAILED と後続の未完了を実行」に | 採用 | 仕様書 §5.2「未完了・失敗した部分だけを続行。成功済みノードは保持」と一致するため採用 |
| 6 | 「業務キーごとに Run は 1 つ」→「同一 network・同一業務キーに対して」 | 採用 | 表の記述を修正(Run の一意性は profile × network × 業務キー — §5.3) |
| 7 | `idempotent: true` は定義者の宣言であることを明記 | 採用 | 三重ゲートの項に 1 文追加 |
| 8 | 「1.0.0 で確認したこと」節を追加し、実測感を出す | 採用 | 単体 579 件、実機 E2E 26 本(P2-01×6・P2-11×5・P2-16×5・CSV×8・m 系 2)、本番 VPS で 8 月末から稼働、R5 の通しセットアップ、を根拠に 6 項目を記載。ChatGPT の候補にあった「START で既存の未完了 Run を迂回できない」は E2E で確認済みだが記事の粒度では省き、「同時起動で Run が重複作成されない」に含めた |
| 9 | 「設計上の判断」を少し圧縮 | 保留 | 5 項目のまま。分量はユーザーの判断に委ねる |
| 10 | タイトルを「kintone のバッチを…」に(定期以外の START・補正 Run も主要機能) | 採用(別案を併記) | 本文タイトルを「kintone のバッチを『ジョブの網』として運用する」へ。検索性重視の旧タイトルはコメントで残し、投稿時に選ぶ |
