# アプリ作成依頼書: FlowNet 1アプリ案

## 依頼概要

FDR D-08の比較案として、FlowNetの現在状態と監査履歴を1つの新規アプリへ保存するアプリを作成してください。既存の実行ログアプリ（4249）はkSQL-Flow所有の別アプリとして維持し、統合しません。

| 仮アプリ名         | app ID     | 用途                                                                                                |
| ------------------ | ---------- | --------------------------------------------------------------------------------------------------- |
| FlowNet 統合 Spike | 作成後記入 | Network Run、Run Invocation、Node State、Node Attempt、Attempt Resolution、bundle、Network Lock候補 |

## 設計規則

- `record_type`で`NETWORK_RUN`、`RUN_INVOCATION`、`NODE_STATE`、`NODE_ATTEMPT`、`ATTEMPT_RESOLUTION`、`NETWORK_LOCK`、`OPERATION_AUDIT`を区別する。
- `record_key`を全record type共通の重複禁止キーとする。
- `node_state_key`と`attempt_key`にも個別に重複禁止を設定する。canonical keyを複合フィールドの代用として最終裁定に使う。
- Node StateとNode Attemptは独立レコードとし、サブテーブルにしない。
- JSON object／arrayは秘密を除去したcanonical JSONとして文字列（複数行）へ保存する。
- 仕様§6の同名フィールドは1つのkintoneフィールドをrecord type間で共有する。record typeごとの必須・許可値はアプリ外schemaとrepositoryで検証する。

## 必要ACL

| 主体                        | FlowNet 統合 Spike                                                                     | 既存app 4249                                   |
| --------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------- |
| FlowNet service principal   | 全record typeの閲覧・追加。Run/State/LockとAttempt lifecycleの限定更新。bundle添付操作 | 相関・開始証跡の閲覧のみ。Job Lock直接更新不可 |
| kSQL-Flow service principal | 原則なし                                                                               | 既存どおり実行ログ・Job Lockを所有             |
| Operator                    | 閲覧、承認済みNetwork回復・解決依頼event                                               | 閲覧。Job recoveryはkSQL-Flow契約経由          |
| Approver / Auditor          | 閲覧、独立承認event                                                                    | 閲覧                                           |
| 一般利用者                  | なし                                                                                   | 既存方針どおり                                 |

1アプリではkintoneのapp ACLだけで現在状態と監査履歴の更新権限を完全分離しにくい点を、Spike Aの測定対象にする。API token値はリポジトリへ保存しない。
