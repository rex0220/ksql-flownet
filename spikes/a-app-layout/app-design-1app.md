# アプリ作成依頼書: FlowNet 1アプリ案

## 依頼概要

FDR D-08の比較案として、FlowNetの現在状態と監査履歴を1つの新規アプリへ保存するアプリを作成してください。既存の実行ログアプリ（4249）はkSQL-Flow所有の別アプリとして維持し、統合しません。

| 仮アプリ名         | app ID     | 用途                                                                                                |
| ------------------ | ---------- | --------------------------------------------------------------------------------------------------- |
| FlowNet 統合 Spike | 作成後記入 | Network Run、Run Invocation、Node State、Node Attempt、Attempt Resolution、bundle、Network Lock候補 |

## 設計規則

- `record_type`で`NETWORK_RUN`、`RUN_INVOCATION`、`NODE_STATE`、`NODE_ATTEMPT`、`ATTEMPT_RESOLUTION`、`NETWORK_LOCK`、`OPERATION_AUDIT`を区別する。
- `record_key`を全record type共通の重複禁止キーとする。
- `node_state_key`と`attempt_key`にも個別に重複禁止を設定する。canonical keyを複合フィールドの代用として最終裁定に使う。
- Node StateとNode Attemptは独立レコードとし、サブテーブルにしない。
- JSON object／arrayは秘密を除去したcanonical JSONとして文字列（複数行）へ保存する。
- 仕様§6の同名フィールドは1つのkintoneフィールドをrecord type間で共有する。kintoneレベルの必須設定は、全record typeが必ず持つ`record_key`と`record_type`だけに設定する。本書の「条件付き」は対象record typeにおける業務上の必須を表し、kintoneでは必須にせず、record type別にrepository層で検証する。
- `record_key`、`node_state_key`、`attempt_key`、`lock_key`の重複禁止フィールドは空値を許容するため、対象外record typeでは空のままとする。

## フォームレイアウト

`PUT /k/v1/preview/app/form/layout.json`で全フィールドを次の順に配置する。各セクションは`LABEL`（表示は`■ <セクション名>`）で開始し、直前のセクションとの間に`HR`を1行置く。表の「行」欄は上から順に配置し、`,`区切りのフィールドは同じ`ROW`へまとめる。`Common`を先頭とする。

| セクション         | 行（上から順）                                                                                                                                                                                                                                                                                                                                                                          |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Common             | `record_key, record_type`                                                                                                                                                                                                                                                                                                                                                               |
| Network Run        | `run_id, network_id, business_key`<br>`max_active_runs, status, lifecycle_status`<br>`resume_allowed, as_of, definition_schema_version`<br>`definition_sha256, source_bundle_sha256`<br>`source_bundle_attachment`<br>`resolved_profile_snapshot`<br>`resolved_profile_sha256`<br>`ksql_flow_version, engine_version, dialect`<br>`created_at, started_at, finished_at`<br>`updated_at` |
| Run Invocation     | `invocation_id, mode`<br>`requested_by, host, result_code`<br>`selected_node_ids`<br>`preserved_node_ids`<br>`blocked_node_ids`<br>`reason`                                                                                                                                                                                                                                             |
| Node State         | `node_state_id, node_state_key`<br>`node_id, job_id`<br>`latest_attempt_no, active_attempt_id, revision`<br>`idempotent, trigger_rule`<br>`blocked_by`<br>`status_reason`                                                                                                                                                                                                               |
| Node Attempt       | `node_attempt_id, attempt_key, attempt_no`<br>`execution_started_at, runner_execution_started_at`<br>`execution_id, duration_sec`<br>`error_message`<br>`read_count, written_count, last_successful_chunk_no`<br>`last_written_key`<br>`state_revision_before`                                                                                                                          |
| Attempt Resolution | `event_type, attempt_id, resolved_outcome`<br>`evidence_ref, service_principal`<br>`approved_by, resolved_at`                                                                                                                                                                                                                                                                           |
| Network Lock       | `lock_key, profile`<br>`owner_invocation_id, lease_token`<br>`lease_expires_at, heartbeat_at`                                                                                                                                                                                                                                                                                           |
| Operation Audit    | 固有フィールドなし                                                                                                                                                                                                                                                                                                                                                                      |
| System             | previewレイアウトから取得した自動生成フィールドの既存行                                                                                                                                                                                                                                                                                                                                 |

共有フィールドはフィールド定義表で最初に該当するセクションへ1回だけ置く。`run_id`、`network_id`、`status`、`started_at`、`finished_at`、`updated_at`はNetwork Run、`invocation_id`、`requested_by`、`result_code`、`reason`はRun Invocation、`node_id`、`job_id`、`revision`はNode State、`event_type`、`evidence_ref`、`service_principal`、`resolved_at`はAttempt Resolutionへ置く。Network LockとOperation Auditはこれらの共有フィールドを参照するが、同じフィールドをレイアウト上へ重複配置しない。フォーム上の全フィールドを要求するAPI仕様に合わせ、フィールド追加後のpreviewレイアウトをGETし、設計表にないレコード番号・作成者・作成日時・更新者・更新日時等の自動生成フィールドを既存の型・コード・行構成のまま末尾のSystemセクションへ置く。自動生成フィールドの実際のコードと行構成は実行時に要確認とする。

## 必要ACL

| 主体                        | FlowNet 統合 Spike                                                                     | 既存app 4249                                   |
| --------------------------- | -------------------------------------------------------------------------------------- | ---------------------------------------------- |
| FlowNet service principal   | 全record typeの閲覧・追加。Run/State/LockとAttempt lifecycleの限定更新。bundle添付操作 | 相関・開始証跡の閲覧のみ。Job Lock直接更新不可 |
| kSQL-Flow service principal | 原則なし                                                                               | 既存どおり実行ログ・Job Lockを所有             |
| Operator                    | 閲覧、承認済みNetwork回復・解決依頼event                                               | 閲覧。Job recoveryはkSQL-Flow契約経由          |
| Approver / Auditor          | 閲覧、独立承認event                                                                    | 閲覧                                           |
| 一般利用者                  | なし                                                                                   | 既存方針どおり                                 |

1アプリではkintoneのapp ACLだけで現在状態と監査履歴の更新権限を完全分離しにくい点を、Spike Aの測定対象にする。API token値はリポジトリへ保存しない。
