# kSQL-FlowNet アプリテンプレート

kSQL-FlowNet が使う kintone アプリ(機械専用の「実行管理」「監査履歴」、人とポーラーが共有する「操作要求」、kSQL-Flow 所有の「JOBログ」)の配布物と、既存アプリを最終形へ追補する Console スクリプトを置いています。

```
templates/
├── ksql-flownet-apps-1.0.0.zip   配布用アプリテンプレート(正)。4アプリを1ファイルでインポート
├── icons/                        アプリアイコン PNG 4種と生成スクリプト
└── console/                      ブラウザ Console 用スクリプト(補助)
    ├── create-flownet-apps.console.js          実行管理+監査履歴の新規作成
    ├── create-flownet-request-app.console.js   操作要求の新規作成
    ├── finish-request-app-views.console.js     ↑が一覧設定で失敗したときの再開
    ├── set-joblog-field-acl.console.js         JOBログの相関フィールドを閲覧のみに
    ├── migrations/                             既存アプリへの追補(適用順は下表)
    └── e2e/                                    E2E fixture アプリ(本番では使わない)
```

## 配布テンプレート(正)

`ksql-flownet-apps-1.0.0.zip` は kintone の **システム管理 → アプリテンプレート** から「kSQL-FlowNet 1.0.0」として登録・ダウンロードしたものです。インポートすると4アプリが同時に作られ、アプリ間参照(実行管理の関連レコード3種)が移行先へ自動で張り替わるため、Run状況プラグインのアプリ ID 自動検出もそのまま機能します。

| 含まれるもの                                                                                                                                                                      | 含まれないもの(導入手順書で案内)                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 4アプリのフィールド・レイアウト・一覧(`00_Run状況` カスタマイズビュー、`01_未処理要求`〜`03_取消済み` など)・関連レコード・アイコン・アプリの説明・実行管理アプリのプラグイン参照 | フィールドアクセス権(操作要求アプリの機械フィールド・`cancel_requested`)、API トークン、プラグイン設定値(START 許可 CSV)、レコード |

インポートの要点:

1. 先にプラグイン zip をシステム管理から読み込んでおく(テンプレートは実行管理アプリにプラグイン参照を含む)。
2. テンプレートをインポートし、4アプリのアプリ ID を控える。
3. 各アプリで API トークンを発行し、操作要求アプリのフィールドアクセス権を設定する(下記「環境変数と API トークン権限」)。
4. JOBログは kSQL-Flow の所有物であり、既存の JOBログアプリを使う場合はインポートされた JOBログを使わず、実行管理アプリの関連レコード `related_job_logs` の参照先を既存アプリへ付け替える。

## Console スクリプト

テンプレートを使わずに開発環境を組む場合や、旧版のスクリプトで作った既存アプリを最終形へ追補する場合に使います。共通の作法:

- アプリ作成・管理権限のあるアカウントで対象スペース(またはアプリ)を開き、開発者ツールの Console へ内容を丸ごと貼り付けて実行する。アプリ ID は `prompt` で入力する
- 変更は preview に適用され、Console の内容確認と `confirm` の後にデプロイされる。キャンセルした場合はアプリ設定画面から「変更を中止」する
- 冪等で、既に存在する項目は変更しない。API トークンや実アプリ ID をソースへ埋め込まない。トークン値を Console やリポジトリへ貼り付けない

### 新規作成(`console/`)

| スクリプト                              | 作るもの          | 備考                                                                                                                                                                                                                      |
| --------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create-flownet-apps.console.js`        | 実行管理+監査履歴 | フィールド・レイアウト幅・`01_要対応ノード`/`02_未完了Run`/`03_停止要求` まで。**`00_Run状況` と関連レコードは含まない**ので、続けて `add-run-board-view` と `add-run-related-lists` を適用する。同名アプリがあれば中止   |
| `create-flownet-request-app.console.js` | 操作要求          | START 3欄(`network_id`・`business_key`・`scheduled_for`)込みの P2-11 schema と `01_未処理要求`/`02_拒否された要求`。**lifecycle v2 は含まない**ので、続けて `add-request-lifecycle-v2` を適用する。同名アプリがあれば中止 |
| `finish-request-app-views.console.js`   | (再開用)          | 上記が一覧設定で失敗したとき、作成済み preview アプリへ一覧2件を設定してデプロイする。`APP_ID` を書き換えて実行                                                                                                           |

### アクセス権(`console/`)

| スクリプト                        | 対象              | 内容                                                                                                                                                                                                                                                                 |
| --------------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `set-joblog-field-acl.console.js` | kSQL-Flow JOBログ | 相関 5 フィールド(`correlation_id`・`attempt_id`・`execution_id`・`job_id`・`runner_execution_started_at`)を Everyone 閲覧のみにする。テンプレートから作った JOBログにも既存の JOBログ(kSQL-Flow template v0.4 以降)にも使う。ランナーのトークン書込は影響を受けない |

操作要求アプリのフィールドアクセス権は `migrations/add-request-lifecycle-v2.console.js` が適用する(テンプレートから作った直後のアプリに実行すると、フィールド・一覧は既存のためアクセス権だけを適用する)。

E2E 用の操作要求アプリは `create-flownet-request-app.console.js` を一時コピーし、`APP_NAME` だけを変えて作ります(正本は変更しない)。本番と E2E でアプリ instance と API トークンを分離してください。

| 3   | `add-triage-views.console.js`          | 実行管理           | 確認ボード用一覧 `01_要対応ノード`・`02_未完了Run`・`03_停止要求`                                                                      |

## 本番用操作要求アプリの gate

1. テンプレートをインポートするか、`create-flownet-request-app.console.js` → `add-request-lifecycle-v2.console.js` の順で作成し、`request_type`(`RERUN`/`STOP`/`RELEASE`/`START`/`CLOSE`)、`request_state`(初期値 `REQUESTED`、終端に `CANCELLED` を含む)、`cancel_requested`(値 `取消` のチェックボックス)、一覧 `01_未処理要求`(`REQUESTED`/`ACCEPTED`)・`02_拒否された要求`(`REJECTED`)・`03_取消済み`(`CANCELLED`)を確認します。
2. 機械フィールド6種(`request_state`、`claimed_at`、`claimed_host`、`claim_heartbeat_at`、`result_code`、`result_message`)は everyone 閲覧のみ、`cancel_requested` は作成者を上位の編集可・everyone を閲覧のみとします。取消は `REQUESTED` の間だけ有効で不可逆です。既存の要求フィールドは編集・削除で再利用せず、毎回新規追加します。
3. ポーラー専用 API トークンは**レコード閲覧・編集のみ**とし、追加・削除権限を付けません。E2E 清掃用トークンとは分離します。
4. 必要なら「`REQUESTED` のまま1時間経過」を条件とする kintone リマインダーを任意設定します。通知は補助であり、一覧確認を置き換えません。
5. 本番のアプリ ID・トークン・絶対 allowlist path を秘密環境ファイルへ設定し、cron を有効にする前に `ksql-flownet poll-requests --check` を実行します。成功するまで本番スケジュールへ接続しません。

START の起動可否は**三重ゲート**(①操作要求アプリのレコード追加権限 × ②VPS 上の allowlist で対象 network に `app_start: true` を明示 × ③network 定義の全実行対象ノードが明示的に `idempotent: true`)で決まり、`app_start` は省略時 `false` です。アプリ側の設定だけでは起動できません。

## 環境変数と API トークン権限

| アプリ                | アプリ ID 環境変数            | API トークン環境変数             | 本番トークン権限                               |
| --------------------- | ----------------------------- | -------------------------------- | ---------------------------------------------- |
| kSQL-FlowNet 実行管理 | `KSQL_FLOWNET_STATE_APP_ID`   | `KSQL_FLOWNET_STATE_API_TOKEN`   | レコード追加・閲覧・編集                       |
| kSQL-FlowNet 監査履歴 | `KSQL_FLOWNET_AUDIT_APP_ID`   | `KSQL_FLOWNET_AUDIT_API_TOKEN`   | レコード追加・閲覧・編集                       |
| kSQL-FlowNet 操作要求 | `KSQL_FLOWNET_REQUEST_APP_ID` | `KSQL_FLOWNET_REQUEST_API_TOKEN` | レコード閲覧・編集                             |
| kSQL-Flow JOBログ     | `KSQL_FLOW_LOG_APP_ID`        | `KSQL_FLOW_LOG_API_TOKEN`        | レコード閲覧(kSQL-Flow 側の書込トークンとは別) |

本番トークンにレコード削除権限は不要です。ロック解放はキークリアまたは tombstone の UPDATE 方式で行います。試験データの清掃で削除権限が必要な場合は、本番トークンと分離した別トークンを発行してください。

実行管理・監査履歴アプリのアクセス権はアプリ管理者とサービスアカウントに限定し、一般ユーザーには閲覧権限のみを付与する構成を推奨します。操作要求アプリでは、要求者にレコード閲覧・追加・編集を許可し(ボードの取消は既存レコードの `cancel_requested` を更新するため、アプリのレコード編集権限が必要)、機械所有の状態・claim・結果フィールドは everyone 閲覧のみにしてください。作成者・作成日時の kintone システムフィールドを要求者の真正性と順序の根拠に使うため、自己申告の要求者フィールドは追加しません。

## 既知の制約

- kintone の `DATETIME` は分精度です。秒精度の実行時刻が必要な処理では、Execution Result や JSONL 側の値を使用してください。
- 一意制約を設定できる文字列フィールドは64文字までです。`record_key` などの一意キーはこの上限内で生成してください。
- kSQL-Flow のジョブロックキーには実測上限があり、各 network 定義で `profile名 + ":" + nodes[].job_id` を 64 UTF-16 単位以内にします。超過は現行 `ksql-flownet validate` では検出されず、実行時に `VALIDATION_ERROR` になります。
- dropdown フィールドのクエリ条件は `in` 演算子を使用します。`=` 演算子は使用できません。
- 複数アプリを1ファイルで配布できるのはシステム管理のアプリテンプレートだけです(アプリ設定からの個別ダウンロードは1アプリのみ)。ACL はテンプレートで持ち出せません。
